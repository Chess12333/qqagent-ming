# 共享接口与唯一写者

依据：施工分阶段目标第 7 行（G1）。本契约记录当前代码中已实现的形状；没有实现的部分明确标出，不在此补造。

## 五类共享接口

| 接口 | 当前实现位置与形状（入参 → 出参） | 提供者 → 消费者 |
|---|---|---|
| 身份 | **两个独立字段，不合并 DTO。** `selfId` 是机器人自身的平台账号 ID：`orchestrator/index.js:171-174` 从 platform 读取并归一为数字字符串；`scenario/evidence.js:123-153,191-225` 的证据构造接收并写入 `MessageEvidence.selfId`。`personId` 是当前主体 ID：`orchestrator/index.js:3303-3310` 从本轮 primary sender 取得（主动私聊轮回退到会话对方）；跨群读取的 `crossChat.personId` 在 `orchestrator/index.js:1465-1528` 使用。**统一身份 DTO：无实现，也不需要合并。** | platform → orchestrator → scenario/evidence 提供 `selfId`；本轮 primary sender → orchestrator → JEV / memory 读取提供 `personId`。两个字段各自解释，不得互换。 |
| 近期窗口 | ChatStore 的 `getChatMeta()` 提供总量与 `sourceRevision`，`readSince(chatKey,cursor,limit)` 提供增量/更正行、`nextCursor`、revision 与 `truncated`（`memory/chat-store.js:763-794,1068-1116`）。编排端 `readPastChatHistory({modules,chatKey,evidence,limit,sessionRegistry,...})` 返回 `history`、锚点状态和 checkpoint（`orchestrator/compose.js:1045-1152`），消息行进入最终请求。另有 JEV 专用近期窗口：编排层取最近消息后传 `judgeOnce`，JEV 将输入裁剪为受限 `recent`（`orchestrator/index.js:3426-3447`、`jev/judge.js:65-84`）；该窗口与主请求历史用途不同。 | memory ChatStore → orchestrator/compose → prompt 请求；编排层局部窗口 → JEV。 |
| JEV 输出 | `buildJudgeInput(input)` 形成 `{focus,recent,keywordHits,activeTopic,memoryAvailability}`（`jev/judge.js:65-84`）；`judgeOnce(input,opts)` 返回状态、`join`、`continue`、`memory:{mode,cross_chat,query}` 及原因/请求信息（`jev/judge.js:91-145,209-285`）。接话字段和记忆字段分别校验。 | jev/judge 提供 → orchestrator 消费接话结果及记忆意图（`orchestrator/index.js:3484-3509,1465-1528`）。 |
| 记忆读取 | 统一入口 `readMemory({route:'retrieve',input:ctx})` / `retrieve(ctx)`（`memory/index.js:402-428,485-495`）。输入包含会话/主体、需要的记忆类型与数量、时间、dataDir 等；跨群另需 `crossChat:{authorized:true,personId}`，记忆层逐条核验 impression-share（`memory/index.js:512-564`）。输出包含候选 `items` 及 dropped/provided/ignored/scanned 等诊断计数。编排层消费结果，compose/prompt 接收已选择的 `crossRoundMemory`（`orchestrator/index.js:1465-1528`、`orchestrator/compose.js:2040-2042`、`prompt/index.js:230,735`）。 | memory 提供检索结果与逐条授权过滤 → orchestrator 选择注入 → prompt 渲染。`cross_chat` 是读取请求，不是授权。 |
| 模型预算 | `createBudgetService({dataDir,hardLimitTokens,softLimitTokens,instanceShares,...})` 提供 `reserve/settle/lookup/getStatus`（`core/budget/index.js:82-95,278-424`）；`executeBudgetedRequest(...)` 先持久预留、执行一次请求并结算成功/取消/未知终态（`core/budget/index.js:485-535`）。LLM `chatCompletionOnce` 将消息、工具、输出上限与可选 signal 交给预算执行（`modules/llm/llm.js:697-707`）；JEV 适配器形成带 purpose 与请求范围的预算请求（`modules/llm/jev-adapter.js:5-61`）。 | server assembly 创建并注入预算服务 → LLM/JEV 调用路径预留、发送、结算；观测/状态读取方用 `getStatus` 查询（`apps/server/assembly.js:805-816,1246-1263`）。 |
